# Testing vibe-history

How to verify the package before trusting it — automated tests, safe installer
dry-runs, and a real end-to-end capture. Every step here is non-destructive:
installer checks run against a throwaway `HOME`, so your real Claude/Codex
config is never touched.

Prerequisite: Node.js on PATH (`node --version`). No other runtime is needed.

## 1. Automated tests

```bash
node --test core/__tests__/*.test.cjs claude/__tests__/*.test.cjs scripts/__tests__/*.test.cjs
```

Expected: all pass (113 at time of writing). Covers the Codex parser, the shared
markdown builder, project/filename/timezone helpers, the backfill runner, the
qmd search wrapper, the Claude capture hook end-to-end (spawns the real hook,
writes files, exercises the kill-switch), and the installer's settings-merge
helper (replace semantics + idempotency).

Enrich-skill config resolver (root must agree with the JS engine):

```bash
cd skills/vibe-history-enrich/scripts
VIBE_HISTORY_ROOT=/tmp/x node -e 'console.log(require("./_config.cjs").defaultHistoryRoot())'   # → /tmp/x
node -e 'console.log(require("./_config.cjs").defaultHistoryRoot())'                             # → ~/Documents/vibe-history
```

## 2. Installer dry-run (safe, throwaway HOME)

Runs the real installer but points `HOME` (and, on Windows, `APPDATA`) at a temp
dir, so nothing on your machine changes.

### macOS / Linux

```bash
SB=$(mktemp -d); mkdir -p "$SB/.claude" "$SB/.codex" "$SB/.gemini/config"
echo '{}' > "$SB/.gemini/config/hooks.json"   # or seed with a real hooks.json to check foreign keys survive
printf '\n' | HOME="$SB" bash ./install.sh
cat "$SB/.config/vibe-history/config.json"   # historyRoot + enabled
cat "$SB/.claude/settings.json"              # SessionEnd + PreCompact hooks
grep notify "$SB/.codex/config.toml"
cat "$SB/.gemini/config/hooks.json"          # 'vibe-history' key with Stop hook
rm -rf "$SB"
```

Check: config written to the canonical path; `SessionEnd` + `PreCompact` carry
one vibe-history hook each; Codex `notify` added; `hooks.json` gained a
`vibe-history.Stop` entry while any pre-existing key (e.g. `orca-status`) is
byte-for-byte unchanged.

To confirm **replace semantics** (safe on a machine that already has an install),
seed the throwaway settings with an old hook + a foreign hook first, then run the
installer and confirm the old vibe-history hook is gone, the foreign one stays,
and yours appears exactly once.

### Windows (PowerShell)

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

Or double-click `install.cmd`. For a throwaway run, launch it from a test
account or a shell where `$env:HOME` / `$env:APPDATA` point at a scratch folder.

## 3. Real end-to-end capture

Prove a session actually lands in the store, writing only to a temp folder:

```bash
TMP=$(mktemp -d)

# Codex — newest rollout:
NEW=$(find ~/.codex/sessions -name 'rollout-*.jsonl' | xargs ls -t | head -1)
VIBE_HISTORY_ROOT="$TMP" node codex/codex-vibe-history-capture.cjs "$NEW" test
find "$TMP" -name '*.md'    # → one file; open it: source: codex, user/agent turns, changed_files
```

The Claude capture path is already covered end-to-end by the test suite (real
hook spawn, real file writes, kill-switch). To exercise it live instead, install
(step 2 against your real HOME), start a new Claude session, do a little work,
then end the session and look in your `historyRoot`.

```bash
TMP=$(mktemp -d)

# Antigravity — newest transcript across all conversations:
NEW=$(find ~/.gemini/antigravity/brain -path '*/.system_generated/logs/transcript.jsonl' -exec ls -t {} + | head -1)
VIBE_HISTORY_ROOT="$TMP" node antigravity/antigravity-vibe-history-capture.cjs "$NEW" "$(pwd)" test
find "$TMP" -name '*.md'    # → one file; open it: source: antigravity, hook_event: AntigravityCapture
```

`argv[1]` (transcript path) can be `""` to exercise the newest-mtime auto-resolve
instead of an explicit path — same code path the `Stop` hook uses. To exercise
the `Stop` hook itself live: install for real, start a new Antigravity
conversation, do a little work, end it, and look in your `historyRoot` for a
`source: antigravity` file.

## 4. Real install per OS (when sharing)

Install for real, then start a **new** Claude/Codex/Antigravity session, do a
few turns, and end it. A `.md` for that session should appear under
`historyRoot`.

- macOS: `install.command` (Finder) or `./install.sh`
- Linux: `./install.sh`
- Windows: `install.cmd` (double-click) or `powershell -ExecutionPolicy Bypass -File install.ps1`

## Known coverage gaps

`install.ps1`'s Claude/Codex sections are verified on **PowerShell 7.x**. It is
written to also work on **Windows PowerShell 5.1** (no
`ConvertFrom-Json -AsHashtable`; BOM-free writes via `[IO.File]`; JSON
generated by Node) — but that has **not** been executed on a real 5.1 host.
The Antigravity section (added alongside Claude/Codex, same pattern: calls
`scripts/merge-antigravity-hooks.cjs` via Node) has **not** been executed on
any real Windows host yet — it was only reviewed for consistency with the
working Claude/Codex sections (no `pwsh` available in the dev environment).
When testing on Windows, run all three sections at least once (ideally on
5.1) to confirm.

Antigravity has no `node --test` coverage yet (unlike the Codex parser and the
Claude capture hook) — verify it with the manual dry-run + end-to-end steps
above.
